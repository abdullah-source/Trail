# DECISIONS.md — binding product decisions (CEO, 2026-09-21)

These override the README where they differ. Change only by editing this file.

## 1. Name, tagline, pitch

- **Name: Trail.** Domain: `trail.app` (fallback `gettrail.app`). Rationale: "trail" means writing in your own hand; it says process and ownership, not policing, and international students can spell it. "Trail" is unownable (generic, taken everywhere).
- **Tagline:** *See how you write.*
- **Pitch (what a student hears):** Trail is a free browser extension that quietly keeps your own record of how each essay gets written: every draft, every session, every source you had open. You get a time-lapse replay of your essay growing, your writing patterns, and an honest AI-use statement written from what actually happened. And if anyone ever questions your work, the record is already there.

## 2. V1 scope

**Ships:**
- Marketing site (static pages, same build).
- Student web app: essay list, essay replay, sessions, patterns, AI-use declaration, evidence-pack export (in the essay "..." menu), settings/billing, invite.
- API: magic-link auth, checkpoints, transparency log, stateless pack builder, Stripe webhooks.
- Chrome extension (MV3): recorder for Google Docs, Notion, Word Online, Canvas/Moodle/Blackboard/Brightspace; paste-source tracking; local IndexedDB store; 10-minute checkpoints (chain heads only); popup shows recording state and per-site pause. The extension dashboard is **removed**; the web app replaces it.

**Where analysis runs — client-side.** Replay, sessions, patterns and declaration are computed in the browser in TypeScript (port of `trail/analysis.py`, `document.py`, `pack.declaration/patterns`), with parity tests against JSON fixtures generated by the Python code. Rationale: the daily views must work without text ever leaving the device; that makes the privacy claim literally true, not a policy.
- The web app reads events from the extension over `externally_connectable` messaging (manifest lists `https://trail.app/*`). No sync of events to the server. Rationale: zero-text server, no data-residency questions for international students.
- Server-side only: signing checkpoints (hashes) and `/v1/pack` (existing: full record posted for one request, built in memory, returned, never written to disk or logs). Pack needs the server's signature, so this is the one moment text transits the server; the UI says so before the click.

**Cut from V1:** Firefox/Safari, Sigstore Rekor publishing, instructor/institution portal, mobile recording, Google Docs per-character provenance (rhythm/paste/append only, as today), team/class plans, AI-detection of any kind, offline pack building.

## 3. Pricing and trial

- **Trial:** 14 days, no card, full features. Hard paywall after (research: hard paywall + trial beats freemium for students).
- **Plans:** Semester **$12 / 4 months** (default, highlighted); Monthly **$3.99**. No annual plan in V1 (semesters match how students think and pay). Prices in USD; Stripe handles local currency display.
- **What never locks:** recording, local storage, raw JSON export, and checkpoint signing continue after the trial. Rationale: a student's record must never be held hostage; that is the whole brand.
- **Referral:** invite 3 friends who each complete a first replay → one free semester for the referrer, stacks up to 3 (Coursicle's 25% conversion).
- **Refunds:** any charge refunded in full within 14 days, one click in Settings, no questions.
- **No dark patterns:** cancel = one click via Stripe Customer Portal, no retention flow; email 7 days before every renewal; price and renewal date on the checkout button; no "trial ending" countdown timers on essay pages.
- Billing: Stripe Checkout (hosted) + Customer Portal; webhooks `checkout.session.completed`, `customer.subscription.updated/deleted` drive `users.plan`.

## 4. Auth

- **Magic link via Resend.** No passwords. Rationale: students on shared laptops forget passwords; magic link is one fewer thing to support and doubles as email verification.
- Session: httpOnly cookie for the web app; the app passes a scoped API token to the extension over externally_connectable after login (replaces the popup email signup).
- **.edu not required.** Rationale: most international and non-US universities do not use .edu. Optional later badge only.

## 5. Tech stack (binding)

- Backend: FastAPI (existing) + SQLAlchemy 2 + Alembic on **Railway Postgres**. Replace `Store` sqlite with a SQLAlchemy repo keeping the same interface; keep `trail/core`, `chain`, `pack`, `record`, `verify` untouched.
- Frontend: Vite + React 18 + TypeScript + Tailwind, built to `trail/server/static/` and served by FastAPI (`StaticFiles` + SPA fallback for `/app/*`). One Railway service.
- Animation: **Framer Motion** (motion.dev). Rationale: React-native API and built-in `useReducedMotion`; the replay time-lapse itself is a custom rAF text renderer, not a library feature, so GSAP's timeline strength is not needed.
- Stripe (Checkout, Portal, webhooks), Resend (magic links, renewal notices), Sentry optional (off by default, `SENTRY_DSN`).
- Extension: plain ES modules as today, no bundler; shared TS analysis compiled to a single file the extension also imports.
- Railway: multi-stage `Dockerfile` (node:20 build → python:3.12-slim), `uvicorn trail.server.app:create_app --factory --host 0.0.0.0 --port $PORT`, healthcheck `GET /healthz`, `alembic upgrade head` in the start command.
- Env vars: `DATABASE_URL`, `TRAIL_SIGNING_KEY` (PEM contents, not path), `SESSION_SECRET`, `APP_URL`, `RESEND_API_KEY`, `RESEND_FROM`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_SEMESTER`, `STRIPE_PRICE_MONTHLY`, `SENTRY_DSN` (optional), `SIGNUP_OPEN`.
- Logging rule: request bodies are never logged; `/v1/pack` logs only user id, event count, duration.

## 6. Information architecture

**Marketing (static):**
- `/` — hero replay time-lapse; one job: get the extension installed.
- `/how-it-works` — what is recorded, where it lives, what the server sees.
- `/pricing` — two plans, trial terms, refund and cancel rules in plain words.
- `/privacy` — exactly what is stored server-side (email, plan, hashes, signatures, timestamps) and what is not (text, events, sources).
- `/terms` — short.
- `/verify` — drop a `.trail.tar.gz`, verified in the browser; public, no login. Job: let a professor check a pack without trusting us.
- `/login` — email box → "check your inbox".

**App (`/app`, authenticated):**
- `/app` — essays list with progress sparklines; empty state drives first-run.
- `/app/essays/:id` — replay (play/scrub), sessions timeline, declaration; "..." menu: export pack (.tar.gz), export JSON, copy declaration.
- `/app/patterns` — when you write, session length, typed share, revision habits.
- `/app/invite` — referral link and progress (0/3).
- `/app/settings` — account, plan/billing (Portal link, refund button), extension status, delete account (wipes server rows; local data stays theirs).
- `/app/welcome` — first-run only.

**First-run (target < 5 min):** Chrome Web Store install → extension opens `/app/welcome` → email → magic link → app pings extension ("Connected") → prompt: "Open Google Docs or Notion and write one paragraph" with a live "recording" pulse → recorder posts first events; app detects them → `/app/essays/:id` auto-opens and plays the replay of that paragraph → one-line CTA to keep writing. Trial clock starts here, not at signup.

## 7. Design brief

- **Audience:** college students 18–25, half international, on laptops between 10pm and 2am, wary of anything that sounds like surveillance.
- **Tone:** calm, plain, on the student's side. Never "detect", "prove", "cheating", "flag". Say "your record", "your replay", "your patterns".
- **Attention = the replay.** Hero on `/` is a real essay growing in a time-lapse: words appear, a paragraph gets deleted and rewritten, a paste lands highlighted with its source chip, session gaps compress. Same component powers `/app/essays/:id`. Motion shows a draft becoming an essay; nothing else on the page moves.
- **Look:** editorial, typographic (one serif for essay text, one sans for UI), warm paper light theme + true dark theme, generous whitespace, real screenshots. Banned: gradient blobs, glassmorphism, 3D robots, purple-on-black "AI" palettes, stock students.
- **Accessibility:** WCAG 2.2 AA contrast, keyboard-operable scrubber, `prefers-reduced-motion` → replay shows draft milestones (25/50/75/100%) with a step control instead of animation; focus rings visible; all text real text.
- **Performance budget:** LCP < 2.5s on mobile 4G, JS ≤ 200 KB gzipped on marketing pages, only Framer Motion beyond React; fonts self-hosted, two weights max; replay uses one DOM node per line, not per character.
- **Mobile:** marketing pages fully responsive; app on phones shows essays and patterns read-only with "install on your laptop" banner.

## 8. Acceptance criteria (all required)

1. `pytest` passes, including new API tests (auth, checkpoints, pack, Stripe webhook, privacy log guard).
2. TS analysis parity: 20 Python-generated fixtures (all writer profiles) produce identical sessions, paste accounting, declaration text and pattern numbers in the browser.
3. `npm run build` and `docker build` succeed; container answers `/healthz` and serves `/` and `/app`.
4. Alembic migrations create the schema from empty Postgres; app boots on Railway with the env vars in §5 only.
5. End-to-end on a clean Chrome profile: install extension → welcome → magic link → connected → write a paragraph in Google Docs and in Notion → replay plays → export pack → `/verify` and `verify.py` both say valid. Under 5 minutes, timed.
6. Stripe test mode: trial→checkout→paid flips `plan`; Portal cancel flips it back; refund button issues a Stripe refund; renewal-reminder email is sent (Resend test).
7. Server never stores text: a test posts a pack, then greps the database dump, data dir and captured logs for a sentinel sentence from the events and finds nothing.
8. `/privacy` lists every table and column stored server-side and matches the Alembic schema (test reads both).
9. Lighthouse mobile on `/`: LCP < 2.5s, accessibility ≥ 95; reduced-motion path works.
10. Extension passes Chrome Web Store review with `host_permissions` narrowed to the editor domains plus copytrack on `<all_urls>`, and a justification text in the listing.
11. No request body logging anywhere (grep CI check).

## 9. Fourteen-day launch plan ($1,000)

- Day 1: buy domain ($20), Chrome Web Store account ($5), submit extension for review immediately (review takes days; do not wait for polish). Railway ($20/mo).
- Days 1–14: founder posts one TikTok/Reel a day: 20-second replay of a real essay growing ("this is what 2,000 words looks like"). Turbo AI grew from ~40 founder videos; ours have a built-in visual.
- Days 3–10: five student micro-creators at $80 each ($400) post their own replay; brief: no script, just the replay and how it felt.
- Campuses: three with the highest international-student share that the founder can visit; $150 for QR flyers in international student offices and libraries; post in each campus's international-student WhatsApp/Discord and r/InternationalStudents with the `/verify` angle only if asked.
- Referral live on day 1; every welcome email ends with the invite link.
- $200 one-week paid test on TikTok targeting the three campuses; kill if install CPI > $2.
- Reserve $205.
- **Measure (weekly, one sheet):** installs → first replay within 24h (activation, target 60%) → day-7 active (target 40%) → trial→paid at day 14 (target 8%) → referral invites per activated user. Stop everything that does not move activation.

## 10. Risks accepted

- Chrome Web Store review may slip the date; accepted, mitigated by submitting on day 1.
- Google Docs canvas means no per-character provenance there; accepted because rhythm, pastes and drafts still give a full replay, and Docs is where students are.
- Porting analysis to TypeScript costs a week; accepted because a zero-text server is the product's only defensible claim.
- "Keylogger" perception; accepted, mitigated by local-only storage, a per-site pause button, and a privacy page that lists tables, not adjectives.
- Institutions may not accept packs; accepted because the pack is a menu item and the daily value stands without it.
- Hand-retyped AI text is undetectable; accepted and stated in the product, never claimed.
- Two plans only, no annual; revisit after 60 days of data.
